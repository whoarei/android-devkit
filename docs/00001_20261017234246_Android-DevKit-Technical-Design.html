Android DevKit技术方案 · Tauri 2

以 Tauri 承载桌面交互，以 Rust 统一管理 Android 工具、设备会话与长任务，让环境准备、模拟器启动和 APK 验证形成可恢复、可追溯的本地工作流。

版本 v0.1 · 技术评审稿创建 2026-10-17 23:42:46（北京时间）依据 PRD v0.6目标 Windows 11 x64

推荐采用 Tauri 2 + React + TypeScript + Rust。 前端负责展示与交互；Rust 负责领域规则、任务执行、文件写入和 Android 工具调用。首版采用单主窗口、官方模拟器独立窗口和本地 SQLite，不引入常驻服务、Node.js sidecar 或完整 IDE。

01 / DECISIONS技术结论与选型

Tauri 适合本产品：主要界面是列表、详情、向导和任务状态，而关键能力都来自本地进程与文件系统。将 Android 操作封装到 Rust，可让桌面界面和后续 CLI / MCP 共享目标绑定、资源锁和审计规则。Windows 使用 WebView2，最终安装体积与内存需在原型上测量，不能仅由框架宣传数字推断。[R4]

Android 工具链正在迁移。 官方已将 sdkmanager / avdmanager 标记为弃用，推荐 Android CLI；但 Android CLI 当前已知问题列有 Windows 的 android emulator 命令不可用。因此首版以“经 M0 验证的传统工具组合”为 Windows 写操作基线，保留新 CLI 适配接口。弃用状态不等于立即不可用，也不能据此假定旧工具能长期兼容所有新包。sdkmanager、avdmanager、Android CLI 已知问题。

不要求用户先安装 Node.js、Rust 或完整 Android Studio。Java 仅在选定 SDK 管理或 AVD 创建工具确实依赖时补齐；已有 ADB 和模拟器能够完成的操作，不因缺少 Java 被统一阻断。

03 / ARCHITECTURE总体架构与工程组织

模块职责与依赖方向

commands 只做 IPC 鉴权、参数解码与 DTO 转换；application 编排用例；domain 定义目标、状态、计划、锁和错误；infrastructure 实现工具、存储和平台接口。长任务由 TaskEngine 持有，不依赖 React 组件、页面路由或一次 invoke 的连接。

Android 进程仍由系统独立运行。主程序负责协调，不把外部 ADB Server、模拟器与自身生命周期强绑定。首版不启用开机后台服务；托盘运行仍是同一个应用进程。

SQLite 使用 WAL、短事务、单写入队列；写入由专用线程处理。数据库记录用户意图与上次观测，不充当 SDK 或设备的最终事实来源。迁移前备份数据库；迁移失败保留原库并报告原因。卸载程序默认保留用户 SDK、AVD 和导出文件。

路径、外部修改与默认目标

路径比较使用 Windows 规范路径与文件身份辅助判断，处理大小写、空格、中文、长路径及重解析点。文件监视仅用于使缓存失效，进入写操作前必须重新读取指纹。配置编辑采用“读取指纹 → 修改允许字段 → 保存前比对 → 同目录临时文件替换”；冲突保留输入，提供重新载入或另存。

默认目标仅保存可靠的逻辑设备身份或 AVD 身份。无线地址和一次 transportId 不作为长期默认设备。只读环境可继续列设备、启动支持的已有 AVD；安装 SDK 与修改配置分别报告目录权限错误，不要求整个应用以管理员身份运行。

把上游变化限制在适配层

接口P0 实现兼容策略
SdkToolAdapter经验证版本的 sdkmanager；读取 package.xml / source.properties 辅助识别本地包保留 Android CLI 的 list / install / remove 实现位置；不根据“程序存在”自动切换写入引擎
AvdToolAdapter经验证版本的 avdmanager 负责创建与支持的删除操作；保守读取与局部更新 INI新 CLI 的 Windows AVD 能力通过实测后再启用；不解析任意自定义批处理
EmulatorAdapter选定 SDK 中的 emulator.exe；独立窗口、能力检测、启动参数与 console 命令图形模式、镜像类型、参数和配置字段按版本白名单限制
AdbAdapter官方 adb.exe 执行设备操作；最小 Rust Host 协议用于无副作用的服务观测不重写 USB、TLS 配对和 APK 安装协议；新旧 Server 能力分别检测

传统工具接受 platforms;android-N 一类 ID；新 CLI 推荐斜杠形式并兼容分号。内部保留标准化结构，只在 Adapter 输出不同语法。两种工具的清单输出都先按已验证文本格式处理，不假设存在通用 --json 参数。Android CLI 包路径、清单输出。

  • 不拼 shell 命令。 所有程序使用绝对路径和参数数组。普通后台命令不弹控制台窗口；模拟器保留自身 GUI。子进程只接收必要环境，清除会覆盖目标的 ANDROID_SERIAL 等变量，并显式设置 SDK、AVD 和 Java 路径。
  • Windows .bat 单独处理。 sdkmanager / avdmanager 在 Windows 常为启动脚本。首版根据已验证的官方工具版本，使用 manifest 中固定的 Java 主类、classpath 和 JVM 参数直接启动 java.exe；不把用户路径拼进 cmd /c。未知启动脚本标记不支持写操作，可选择应用私有已验证工具，不覆盖原 SDK 工具。
  • 同时排空 stdout / stderr。 使用有界队列与尾部日志，适配换行、回车进度、ANSI 控制符及编码；不可因 WebView 消费慢阻塞子进程。文本解析失败保留诊断尾部并返回“结果待检查”。截图始终走二进制管道。
  • 进程身份可验证。 记录 PID、创建时间、可执行文件路径和所属任务；强停前重新核对，防止 PID 复用。不按进程名批量终止 adb / emulator / java。
  • 生命周期分级。 普通任务使用受控进程树；只在该阶段允许取消时结束树。共享 ADB 不加入退出即杀的 Job Object。模拟器使用不随主程序关闭终止的策略，日志直接写文件，不依赖退出后会关闭的 stdout 管道。

工具兼容清单至少记录：版本与哈希、Java major、可用操作、已知输出格式、配置字段、代理能力、取消语义与样本集。不能把任意“最新版”视为兼容。

06 / BOOTSTRAP环境发现与首次安装

SDK 的引导步骤与 app 安装是两件事。用户完成工具安装后应能在普通权限下使用；涉及 Windows 功能、驱动或重启时，仅给出检测事实与用户操作入口。

清单与变更计划 SDK-01～03

系统镜像树使用 API → 镜像类型 → ABI → 组件四层结构。类型优先按规范组件 ID 的第三段识别 AOSP、Google APIs、Google Play，避免 page_size_16kb 等通用元数据标签造成归类错误；未知类型保留独立分组。ABI 从 ID 第四段读取，空缺时使用元数据。选择状态绑定包 ID，展开状态按分类 / 搜索 / 状态筛选作用域保存；搜索与筛选默认展开匹配路径，全展开 / 收起遍历所有分支，各级数量与更新提示按筛选后的子项计算。

界面采用 SDK Platforms / SDK Tools / SDK Update Sites。平台按 API、工具按包 ID 首段分组；搜索与安装 / 更新 / 待变更筛选组合，稳定与预览修订号按数值比较。四个内置源及自定义 HTTPS repository / remotePackage XML 逐源解析并保存状态；限制来源数量与 XML 体积，自定义源包 ID 冲突拒绝加载。sdkmanager 使用应用私有 ANDROID_USER_HOME / repositories.cfg，仅注册当前已确认组件的自定义源，附加所选频道参数，不修改用户 Android Studio 源配置。目录刷新串行化，保存前再次核对设置；来源设置改变使旧计划失效。分类与站点交互参考 Android 官方 SDK 管理说明。

本地清单优先读取实际安装记录，结合受支持工具查询；远端清单保存来源、获取时间、频道和原始输出样本。断网可展示上次远端目录，但标记过期，已安装清单与启动已有设备仍可用。推荐规则基于目标架构、用户选择和已装版本，不固定某个 Android API。

RepositoryCatalog 按兼容清单配置的官方仓库源读取版本化元数据，补齐 CLI 列表通常不能完整提供的下载体积、归档校验值、依赖、许可文本与镜像标签。它只为浏览和预检提供信息，普通组件仍由官方工具安装；按命名空间维护解析器，禁用外部实体，约束 XML 大小，并交叉核对包 ID 与版本。元数据缺失时显示未知 / 估算；不能猜出一个精确下载量或默认为已接受许可。

用户勾选后只生成不可执行的草稿。确认时计算依赖、许可、空间、已知引用与单例组件替换关系；生成带 planHash 和环境指纹的 Plan。执行前获取 SDK 锁、重新检查实际清单；版本、许可、源或风险变化时返回重新确认。

逐项执行与事实复查

  • 计划按依赖顺序逐项执行，每项保存状态。组件成功要求退出结果与本地包记录一致；已完成项保留。失败后重试原未完成项，重新检查是否已被外部工具完成，避免重复写入。
  • 平台、Build Tools、系统镜像按包 ID 可并存；platform-tools、emulator 等同路径组件展示替换影响。既有模拟器在运行时阻止替换正在使用的 emulator / 镜像；共享 ADB 在运行时不直接覆盖其程序文件。
  • 卸载镜像前从已知 AVD 读取镜像引用；仍引用则阻止。当前任务与运行实例持有读租约时禁止卸载。外部项目依赖无法完全得知，确认中展示这一事实；不能把“未发现引用”写成绝对安全。
  • 使用 SDK 根的应用内互斥锁和实例锁；官方工具锁、文件占用与外部配置变动是额外证据。不能宣称应用锁能约束 Android Studio，发现并发写入时停止提交并刷新清单。
  • 多项变更不是全局原子事务；混合增删计划展示具体执行顺序与每项影响。以“部分完成”表达真实结果，不自动卸载已安装组件来模拟回滚。

代理、进度与取消

引导下载和官方 SDK 工具分别接入同一份网络设置，但按各自能力映射。P0 保证直连与经验证的手动无认证 HTTP / SOCKS 代理；需要身份认证或 PAC 时展示工具能力限制和本地代理入口。凭据如有保存需求由 Windows 凭据存储保护，不写命令行或任务日志。SDK 代理不会自动修改 Android 客体网络代理。

网络测试访问当前实际目录源与包下载源，区分 DNS、TLS、代理认证和校验错误。TLS 校验失败不降级 HTTP 或关闭证书校验。目录解析失败时不靠猜测启动安装。

进度按 Adapter 能可靠观察到的阶段展示；未知字节数显示不定进度和最近输出。传统 SDK 安装的内部下载不提供本应用可保证的暂停 / 续传，因此 P0 默认不显示暂停按钮。取消请求可标为“当前组件完成后取消”；只有适配器证明当前阶段安全可终止时才立即结束。应用自有引导下载可在服务端支持 Range 且 ETag / Last-Modified 一致时续传，否则重下当前文件。

08 / VIRTUAL DEVICESAVD 管理与启动

发现与配置编辑 AVD-01 / AVD-04

建立 AVD 定义清单，读取注册 INI 与真实数据路径、系统镜像、硬件 profile 和允许字段；缺配置或镜像的条目保留并说明原因。运行会话通过 adb emu avd name 等可靠证据关联回定义，结合已记录启动实例判断。同名、型号或端口相似都不足以自动关联。

显示名与内部名分离。新建内部名采用受限 ASCII 字符和唯一性检查；既有内部名保持不变，P0 的改名只改受支持的显示名。内存、存储与图形字段按版本和镜像限制验证；运行中禁止修改，未知键与原始格式保留。外部更改冲突按第 04 节处理。

高级配置覆盖 CPU / RAM / VM Heap、显示、摄像头、网络、启动、存储、皮肤与输入能力。前端固定打开时的配置指纹，只提交变更字段；后端使用白名单、数值与文件校验，再比对指纹原位保存。网络速度 / 延迟映射 runtime.network.* 并在启动时传入 -netspeed / -netdelay；无皮肤使用分辨率 skin.name 和空 skin.path。新 SD 镜像使用 mksdcard 生成唯一文件，创建暂存提交时修正最终路径；标记为自有的镜像在清数据时重建并清除 qcow2 覆盖层，外部镜像保留。清理前检查其他登记 AVD 的存储引用。容量修改不自动擦除用户数据。选项参考 官方 AVD 属性说明，映射经本机模拟器验证。

创建采用可恢复的分步提交 AVD-02

  1. 选择手机 / 平板和受支持硬件 profile；选择 Android API、AOSP / Google APIs / Google Play 与主机匹配的 ABI。Play 镜像还需满足硬件 profile 能力，不混同为普通 Google APIs。
  2. 生成依赖计划并完成许可、镜像准备与加速检查；对同一名称和路径获取创建锁。任务意图入库后，在目标卷的专用暂存区执行官方创建工具，使用隔离的 AVD 注册目录，避免半成品进入用户列表。
  3. 验证配置引用与数据目录，提交数据目录，再写入正确的 path / path.rel 注册信息；注册入口最后发布。不覆盖已有同名 AVD。跨文件操作由提交日志追踪，不能宣称整体原子。
  4. 提交前取消只清理有本任务标记的暂存对象；已完成共享镜像保留。提交中异常重开后按提交日志复查并完成或撤销本次发布，不重新生成第二台设备。自动启动仅来自用户已勾选的选项。

启动、就绪与进程归属 AVD-03

stopped → launching → waiting_adb → waiting_boot → ready
启动超过 180 秒 → 显示超时提醒；进程与设备事实继续独立更新

启动前检查镜像、写权限、占用、主机资源与 emulator -accel-check。Windows 优先指导 WHPX；官方已公告 AEHD 于 2026-12-31 结束维护，不把旧驱动作为新环境默认安装项。图形模式默认 auto，软件回退使用当前版本支持值。硬件加速与驱动生命周期。

启动参数使用 emulator -avd <name>；冷启动额外添加 -no-snapshot-load，绝不以清数据代替冷启动。进入 ADB 的 device 状态后，检查目标 AVD 关联、sys.boot_completed=1 与包管理服务响应；探针按系统能力降级并保留原因。启动超时不自动杀进程或认定启动失败，提供继续等待、日志与显式停止。模拟器参数。

同一 AVD 持有运行租约，阻止重复启动及修改；外部工具启动的实例同样通过官方锁、会话和进程证据识别。正常停止先向明确关联的模拟器发送退出请求，等待实例消失；超时后单独确认强停，按 PID、创建时间及程序路径重新核验目标。无法证明归属时只提供手动处理说明。

“打开窗口”通过已验证进程链定位顶层 HWND，尝试恢复和聚焦；受 Windows 前台切换限制时闪烁任务栏并提示。外部以嵌入或无窗口方式启动的实例可能没有独立窗口，此时说明事实，不另起重复实例。

清除数据与删除的真实边界

清除数据：先停止并检查占用，经明确确认后使用经验证的 -wipe-data 流程。该选项通常伴随启动，且不会清除独立 sdcard.img；产品既然承诺重置该 AVD 用户数据，就必须单独列明并清理归属已确认的用户 SD 卡与快照状态，保留硬件配置和共享镜像。M0 验证受支持文件集合与官方流程，任务最终回到停止；取消或清理不完整只能标为部分完成 / 待检查，不能宣称完整出厂重置。wipe-data 与 SD 卡边界。

删除 AVD：确认注册文件、数据目录、可回收占用和已知关联，优先用受支持官方删除接口。SDK 根、镜像根、其他 AVD、任意外部路径都不能被联动递归删除；符号链接 / junction、共享数据路径或无法证明范围时阻止操作。完成后复查注册和数据，重新统计释放空间。强停、清数据与删除互不隐含。

09 / ADB & SESSIONSADB 共存与设备会话

共享 ADB 的协调策略 AC-11

默认使用 Windows 主机本地 127.0.0.1:5037 的共享 ADB Server，复用普通用户的授权体系。P0 不默认起第二套端口服务，也不代理 WSL。工具路径、客户端版本、Server 能力与来源在诊断页可见。

不能只约束“不调用 kill-server”。 某些 ADB 客户端在发现不兼容 Server 时会自行结束并替换服务。因此发现阶段先用最小 Host 协议只读查询 host:version，支持时读取 host:server-status；再选兼容客户端。未知或冲突时先阻止会触发替换的命令，由用户选择兼容工具或确认重启影响。AOSP Host 服务协议。

无 Server 且用户需要设备功能时，才通过选定客户端启动本地服务；此后原始 Host 连接订阅设备变更，受支持时读取详细设备列表，失败退为有界轮询。实现仅覆盖帧长度、OKAY / FAIL、版本与列表等有限协议，并约束超时、最大帧及解析长度；设备写操作仍使用官方 adb。

Server 连接丢失或重启即更新 serverEpoch 并使旧会话失效。每次写操作前检查兼容性和当前会话；监控发现外部替换时停止分派。外部进程可能在检查后立即替换服务，无法获得全机原子锁；此类竞态按目标丢失或结果未知处理，不自动反复重启来争夺服务。

  1. 文件对话框与 Tauri 文件拖放事件均进入同一入口；拖到设备行时传候选设备，空白区使用已选目标或弹出选择器。后端验证普通文件、可读性、单 APK、ZIP 结构与大小，拒绝 AAB、APKS / XAPK 或多文件安装。

  • 后端使用 10,000 行且总量不超过 8 MiB 的环形缓冲；超长单行截断并标记。前端虚拟列表按批量刷新，避免逐行 invoke / Event。达到任一上限滚动淘汰，显示丢弃计数。
  • 应用过滤跟踪包对应进程集合而非永久绑定一个 PID；初始按 2 秒周期及进程变化信号刷新，处理主进程与受支持子进程。PID 缺失显示“等待应用进程”，不伪装无日志；无法归属的隔离进程明确显示过滤覆盖范围。
  • 暂停只停止视图跟随，后台缓冲仍有界更新，恢复时提示缺口；“清空视图”建立视图游标，不执行 logcat -c 清除设备全局缓冲。应用重启或设备重连时标记新的采集段。
  • 长采集作为独立任务直接流式写文件，按初始每段 100 MiB 轮转，启动前确认总配额或时限。磁盘不足停止并保留已完成段；对设备断线、权限限制或队列溢出写入缺口标记。视图关闭只结束自己的订阅，不终止明确启动的文件采集。

截图与剪贴板

执行 adb -t <id> exec-out screencap -p，二进制 stdout 直接写入暂存 PNG，验证退出结果、PNG 签名及图像解码后返回 artifactId。预览通过受限本地资源读取，文件路径不直接授予 WebView 任意读取权。官方截图方式。

环境摘要与导出隐私

摘要包括 OS、环境能力、工具来源与版本、设备系统、任务阶段、错误码与建议动作。默认替换用户目录、设备标识、IP、配对数据和可识别敏感字段；同次导出使用一致占位符以便关联。日志与截图可能含应用数据，规则脱敏无法保证覆盖自由文本和图像，因此导出前提供实际内容预览与选择范围。复制设备标识是独立、由用户主动执行的动作。

12 / TASK ENGINE任务调度与异常恢复

状态与取消语义

任务中心通过只读 task_list(TaskQuery) 查询完整 SQLite 历史，关键词匹配任务名、结果、任务 ID、设备 / 地址及相关组件，输入按参数绑定且通配字符按字面量处理。状态支持全部、进行中或明确状态；返回当前关键词下的状态计数、筛选总数与每页 30 条记录，在途优先、同组按创建顺序倒序。查询在线程池执行，末页因后台状态变化变空时回退到有效页；任务事件同时使工作空间快照与任务查询失效。前端以两行摘要呈现，展开才挂载诊断与采集导出，许可确认保持直接可见。

draft → awaiting_confirmation → queued → running
running → succeeded | partially_succeeded | failed | cancelled
异常中断 → needs_reconcile → 实际复查 → 已确认结果或 needs_review

设备状态、任务状态和任务阶段分别建模。running.phase 可为 preparing、downloading、verifying、installing、waiting_device、checking_boot 等，记录已知百分比或未知进度、最后更新时间和是否可取消。needs_reconcile / needs_review 在界面显示“结果待检查”，不是成功状态。

取消策略由步骤声明为 immediate、after_step 或 not_cancellable。点击“取消”只写入请求；只有执行器确认没有继续产生副作用才转为 cancelled。写入提交中显示“此阶段完成后取消”；若当前最后一步已成功完成，则报告完成并说明取消请求到达较晚，不伪造取消成功。

14 / WINDOWS SHELLWindows 窗口与退出

自绘标题栏实现 WIN-01 / AC-13

窗口采用 Tauri 2 的 app.windows 配置，关闭原生装饰并保留可缩放、最大化与任务栏行为。默认尺寸建议 1280 × 800 逻辑像素，最小 960 × 640；标题栏 40、按钮 46 × 40 逻辑像素。窗口样式保持非透明，先减少复杂合成与命中测试风险。Tauri 窗口定制。

  • 只有标题栏空白区可拖动；交互控件排除拖动。双击通过统一窗口动作切换最大化，避免 DOM 与原生处理重复触发。按钮使用可访问名称和键盘焦点。
  • 最大化图标来自真实窗口状态：启动、resize、focus、恢复与 DPI / 显示器变化后重新查询，不能用点击次数维护布尔值。恢复位置按当前显示器工作区修正，避免断开显示器后窗口出屏。
  • WindowsAdapter 使用原生 HWND 消息与命中测试保留边缘缩放、系统菜单、Alt+Space、Win+方向键、最大化拖动还原与工作区边界。

最大化按钮的悬停贴靠是前置验证项。 自绘 HTML 按钮不保证自动出现 Windows 11 Snap Layout。微软要求自绘标题栏正确响应非客户区命中测试，例如最大化区域返回 HTMAXBUTTON。需验证 WebView2 子窗口、原生区域与点击消息转发的共同作用，不能只加一段 CSS 或父窗口 WndProc 就认定完成。微软 Snap Layout 指引。

M0 对比 Tauri 锁定版本的现有能力与小型 Rust 原生标题栏桥接：为控制区维护真实物理像素矩形，在 DPI、缩放和布局变化时更新；必要时以原生命中区域承接非客户区消息，同时让 DOM 展示与可访问性状态一致。若依赖的框架无法覆盖，完成该桥接后再通过 WIN-01，不能把只有 Win+Z 可用视为悬停贴靠已验收。

关闭、托盘与退出状态机

所有关闭入口，包括自绘按钮、Alt+F4、任务栏关闭，均由 Rust 的 CloseRequested 进入统一策略；前端只有请求入口。未启用托盘且无在途任务 / 未保存产物时退出；有任务时阻止立即退出，显示任务与阶段，提供“返回”“完成任务后退出”“取消任务并退出”。后两项均等待必要收尾，不能截断组件写入。

“完成后退出”进入 draining：停止接收新写任务，现有有限任务完成后退出；无限日志采集需用户先选择停止并完成文件封口，不可无限等待。取消退出按步骤取消能力执行；未保存截图与导出结果提供保存或明确放弃。

托盘默认关闭，用户显式启用后关闭窗口改为隐藏，首次解释行为。托盘保留任务数、失败提示、恢复窗口与退出入口；菜单“退出”仍走统一流程。应用退出默认保留模拟器和共享 ADB，释放观察连接；只有用户主动选择停止实例才发送停止请求。

系统注销 / 关机可能不给完整对话与等待时间，不能依赖最后一刻弹窗保证安全。任务意图和日志持续落盘，正常退出时收尾，强制结束后由恢复流程报告真实结果。单实例插件唤起现有窗口，避免重复管理同一 SDK 和 AVD。

15 / SECURITY权限与安全边界

发布版本只加载随包静态前端，禁止远程页面导航和远程内容获得 IPC；帮助链接交给系统浏览器，按固定协议和来源校验。CSP 从 default-src 'self' 起按 Tauri 本地资源实际协议配置，不启用任意脚本、远程 CDN 或通配连接。日志、包名、设备名和工具输出始终按文本渲染。

边界实现要求
Capabilities权限只绑定 main，显式列出所需窗口查询 / 最小化 / 最大化 / 拖动与对话框能力；不直接授予任意 shell、任意文件系统、SQL、进程退出或动态窗口创建权限
自定义 Rust commands通过 AppManifest::commands 与自定义 permissions 纳入 ACL，并核验调用窗口。Tauri 默认注册的应用命令不会仅凭写了 capability 文件自动全部受限；后端仍须校验每个动作和范围。Tauri capability 与自定义命令规则
用户选中文件与导出对话框 / 拖放建立短期文件句柄或 artifact 引用；路径 canonicalize 后检查用途。保存与覆盖由本次授权限定，不暴露 read_any / write_any 接口
设备与高影响动作确认摘要由 Rust 生成；短时一次性令牌绑定对象、计划哈希及影响范围。清 AVD 数据、删 AVD、卸载重装、SDK 卸载、重启共享 ADB 与强停分别确认
删除与解压检查解析后的真实路径、根目录边界、重解析点和对象归属；执行前复查文件身份，避免字符串前缀误判与路径变化。拒绝对磁盘根、SDK 共享根和来源不明目录递归删除
凭据与隐私配对码只在内存；不读取、复制或导出 ADB 私钥。日志默认脱敏且限额保留；用户主动选原始日志时展示内容预览
应用更新与工具下载下载经 HTTPS 和固定发行校验；更新包签名独立校验。Android 工具升级需用户显式触发，不能随应用升级静默改写用户 SDK

Rust 本身拥有本地系统能力，Tauri ACL 不能约束有缺陷的 Rust 代码。因此安全检查放在领域服务与基础设施写入入口，不能只靠隐藏按钮或关闭前端插件。Android CLI 若后续启用，默认使用官方的 --no-metrics 选项，并不更改用户全局配置。Android CLI 数据收集设置。
