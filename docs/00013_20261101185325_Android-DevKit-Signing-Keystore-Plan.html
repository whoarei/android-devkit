01 定位与用户场景

作为独立工具页，服务于已经拥有 APK 或准备签名材料的开发者。继续由外部编辑器与构建工具产出应用，DevKit 负责本地签名材料与产物操作。

场景用户要获得的结果
接手已有应用登记文件位置、用途、关联包名与备注，确认有哪些 alias，找到需要使用的密钥。
配置第三方服务复制 SHA-1 / SHA-256 指纹或导出公开证书，明确来自 debug、上传还是应用签名证书。
准备新的签名材料通过表单新建 Keystore，查看最终位置、alias 和证书；完成后提供“打开所在目录”和备份指引。
确认一个 APK 的签名看到完整性验证结果、实际签名者和指纹，与所选证书做明确比较。
给本地测试或分发包签名选择 APK 与密钥，另存经过验证的新 APK；需要时再明确选择设备安装。

上传密钥与应用签名密钥是不同角色；使用 Play App Signing 时，Google Play 分发 APK 的证书可能与本机上传证书不同。页面分别展示角色和实际指纹，角色是用户备注，不能当作官方注册状态。依据：Android 应用签名说明。

02 第一轮功能范围

编号能力交付边界
SK-01登记与管理选择已有文件，登记名称、路径、用途、关联应用和备注；支持重新定位、刷新信息、移除记录。登记引用原文件，不建立永久私钥副本；移除记录保留原文件。
SK-02Keystore 查看读取 JKS / PKCS12，支持常见 .jks / .keystore / .p12 / .pfx 文件名；显示实际格式、alias、条目类型、算法、证书主体 / 颁发者、有效期及指纹。多 alias 逐项展示，纯证书条目可查看、不能用于签名。
SK-03新建 Keystore仅向新的目标文件生成一个私钥条目；格式、alias、密码、证书信息和有效期可确认。生成后重新打开校验，保护尚未保存完成的密钥。
SK-04公开证书导出复制 SHA-1 / SHA-256，导出 PEM 或 DER 公开证书。可读取单独的 .pem / .cer / .der 证书作比较；不将证书导出称为“私钥备份”。
SK-05APK 校验与证书对比识别未签名、验证失败、验证通过及工具无法确定的情况；展示签名者和可可靠识别的签名方案。只比较证书，不以指纹相同直接承诺可以覆盖升级。
SK-06单 APK 签名支持未签名完整 APK，以及可确认单签名者且无轮换谱系的普通已签名 APK；已有签名需勾选“覆盖原签名”。输出可选择新文件或覆盖已有文件；可独立勾选“覆盖源文件”，不再选择输出路径，签名及校验完成后替换源 APK。目标文件变化时拒绝覆盖。
SK-07结果与安装衔接结果显示输出位置、摘要、使用的证书与验证信息；可打开目录、复制信息或进入现有 APK 安装面板。安装由用户选择目标并单独确认。
第一轮排除：AAB / APKS / APKM / XAPK 与整组分包签名、多个签名者写入、密钥轮换和 lineage 生成、修改既有 Keystore 的密码 / alias / 条目、私钥明文导出、密码保险箱、云端同步、商店上传和 Gradle 项目配置修改。第一轮不生成 v4 的 .idsig 旁车文件。

多签名者或已知轮换谱系 APK 可以做工具支持范围内的只读校验；无法可靠判断重签是否会丢失既有谱系时，阻止重签并解释原因。输入能否独立安装与签名能否通过分别说明。

04 核心操作流程

A. 登记已有 Keystore

选择文件不扫描整块磁盘
→
提供本次密码读取并校验容器
→
查看 alias 与证书确认实际格式
→
保存登记信息名称、用途、关联应用

同一路径重复登记时打开已有记录；不同文件包含同一证书时提示重复证书，允许分别登记。文件暂不可读时可仅登记路径，但标为“待校验”，不产生“密钥可用”结论。关联包名仅用于查找与提醒，不限制该证书可签署的包名。

B. 新建 Keystore

填写新文件位置、格式、alias、密码及证书信息 → 核对摘要 → 生成 → 重新打开检查 → 发布文件并登记。发布成功显示证书信息、文件位置和“请另行备份此文件与密码”的操作指引。

建议默认：PKCS12 / .p12，RSA 3072，SHA256withRSA，10950 天（约 30 年）；兼容选项为 JKS / .jks。新建密码至少 12 个字符并再次确认，不将此限制套到已有文件。PKCS12 新建使用同一个容器与私钥密码，JKS 可在高级选项分别设置。JDK 9 起默认格式为 PKCS12，实际调用仍显式指定类型；Android 建议证书至少有效 25 年。依据：keytool 格式与密码说明、Android 证书有效期建议。

新建默认参数属于本产品方案；不依据扩展名猜测文件真实格式。新建第一轮仅提供这一套算法配置，已有 RSA / EC 条目能否签名以工具能力检查为准，其他条目可只读展示。实测 Java 的 PKCS12 新建仅接受 ASCII 密码，页面明确提示；JKS 支持中文密码及不同的私钥密码，新生成 JKS 会经标准 Java API 重新封装核验，保证可供 Java / Gradle 使用。

C. 校验与对比 APK

选择或拖入 APK → 读取包信息并验证签名 → 展示签名者 → 可选 Keystore 的某一 alias 或独立公开证书作对比。结果使用“当前证书一致”“当前证书不同”“无法确定”，同时保留签名验证结果和原始适用范围。已登记应用备注不影响比较结果。

“APK 签名”页的检查结果仅保留包名、版本及签名状态，不展开证书主体、颁发者、有效期和指纹。点击“查看签名详情”进入“APK 校验”，沿用同一文件及已有检查结果。

比较基于证书 DER 的 SHA-256；SHA-1 仅作为第三方服务常用标识展示。有效签名说明产物在工具检查范围内完整且可验证，不代表发布者可信、应用安全、业务正常或一定能覆盖设备上的版本。

D. 签名并交给现有安装流程

选择完整 APK识别原有签名
→
选择 Keystore / alias提供本次所需密码
→
核对签名计划证书、包信息、输出
→
执行并验证保留输入原件
→
另存并可选择安装单独选择目标设备

确认页以文件、输出目标和密钥分组显示，包名 / 版本 / 大小位于顶部；不再提供“证书与执行详情”，移除指纹、执行流水和重复说明，展示路径时去掉 Windows 规范前缀。默认输出名为 原名-signed.apk，可覆盖已选择的已有目标；相对输出路径自动转为绝对路径。勾选“覆盖源文件”后仅展示并突出同一源文件作为覆盖目标，主按钮为“签名并覆盖”；选择已有输出时也显示“覆盖输出文件”与“签名并覆盖”；新文件为“确认签名”。

执行阶段依次为：复制并核对输入快照 → 检查或修正 ZIP 对齐 → 签名 → 校验新签名与对齐 → 发布输出。对齐必须在签名前；签名后仅做读取校验。包含未压缩 .so 时按工具能力采用 16 KiB ZIP 对齐，但此检查不能证明 ELF 或应用本身已兼容 16 KiB 设备。依据：apksigner、zipalign。

05 密钥、密码与签名规则

对象第一轮规则
密码生命周期仅进入专用授权命令和运行时内存，不进入 Operation.args、Plan、SQLite、用户偏好、任务历史、诊断、前端存储或命令行参数。单次授权绑定计划摘要、requestId、输入摘要与 alias，未开始执行时 5 分钟失效；消费后不复用，任务重试重新授权。
进程输入当前实现通过自有 Java 桥调用官方 apksigner.jar 的 ApkSigner / ApkVerifier API，以有长度边界的 UTF-8 stdin 传递密码；keytool 使用受控标准输入生成容器。避免 CLI 密码检索对 Unicode 的差异，不发送到交互终端，不生成密码临时文件，也不放入环境变量或命令行。明确拒绝 NUL / CR / LF；JKS Unicode 双密码在 Java 21 / 24 实测。
日志与内存任务只记录白名单阶段与结构化结果；工具原始输出先做敏感内容过滤，再允许进入用户日志。Rust 敏感类型避免 Debug / Serialize / 无约束 Clone，结束时尽量清零；前端关闭面板立即清空引用。不能依赖现有正则脱敏来补救已持久化的密码。
文件快照登记不建立永久私钥副本。签名执行可创建所选加密容器的短时任务快照，并复制 APK，完成后核对与已确认摘要一致；快照限制当前用户访问，签名结束后清理。普通缓存清理不触及用户原文件及待保存的新密钥。
输出文件APK 签名可保存到新文件或覆盖选定的已有输出；相对输出路径自动转为绝对路径。确认已有输出的摘要，验证签名后使用同目录暂存与原件备份替换；确认后目标变化时停止覆盖。新建 Keystore 仍只使用未占用文件名；原先不存在的目标在发布前出现同名文件时等待另存。
显式覆盖源 APK仅适用于 APK 签名，默认关闭；输出绑定到规范化的输入路径。验证完成后复制到同目录暂存，重新核对源摘要，再以 Windows ReplaceFile 替换并保留短时原件备份。失败时保留源文件或恢复材料与已验证结果；启动复查不会自动重放签名或覆盖外部变化。恢复材料未处理时保护任务记录。
签名参数采用工具根据 APK minSdkVersion 选择的常规 v1 / v2 / v3 策略，不在第一轮暴露任意组合开关，也不改写 Manifest 的 SDK 要求。显式关闭 v4 旁车生成；最终界面只展示工具可靠识别的验证结果。
证书状态证书过期、尚未生效、工具报告算法不支持时阻止本轮签名，并仍允许查看。到期不足一年给提示；角色、有效期与签名完整性分开显示。多 alias 必须显式选择，不能默认取第一项。
设备与外部环境签名无需 ADB；不自动修改系统 PATH / JAVA_HOME，不编辑项目文件，不卸载手机应用。安装必须复用现有目标冻结与确认规则。

对缺少密码完整性校验、容器损坏、错误密码或实现不支持而无法准确区分的情况，使用“无法解锁：密码、文件或格式不匹配”，不凭一个错误字符串断定文件损坏。密码错误无无限自动重试。

06 异常与结果恢复

情况反馈与处理
Java 可用但缺 keytool分别显示工具能力，允许继续已有的 APK 只读校验；Keystore 操作引导选择包含 keytool 的运行时。不把 java.exe 成功启动当成全部工具就绪。
Build-Tools 缺失或版本不兼容生成当前用途的最小依赖计划，沿用许可与下载流程；完成后返回原页面保留非敏感选择，重新提供密码。
文件移动、外部修改或工具变化记录保留并标记缺失 / 待复查；执行前重新比对输入、证书及工具快照，变化后要求重新确认，不能继续使用旧指纹。
签名失败、验证失败或空间不足不发布未验证的内容；另存时保留输入原件，覆盖时保留目标文件或原件恢复材料。已验证输出因目标冲突或保存失败而未发布时保留到待处理结果，允许另存同一输出。
新密钥生成后中断或登记失败保留已经生成的同一加密容器，恢复时先复查已发布文件或待保存文件。重试保存原结果，不能静默重新生成一把不同密钥。任务记录和文件受保护，用户明确保存或放弃前不允许普通历史清理删除。
取消与进程异常退出生成前可取消并清理任务临时文件；生成后先保护新密钥。签名中取消仅终止本任务拥有的工具进程，不影响共享 ADB、模拟器或用户文件；任务恢复为待检查，重新确认和授权后重试。
最小化、关闭及完整退出沿用 v0.6.1：最小化 / 关闭隐藏到托盘，已提交任务继续；未提交的密码面板关闭时清空输入。真正退出前检查在途任务和待保存结果；新的 Keystore 结果加入同一保护范围。

新建 Keystore 是需要特别保护的结果：普通“忽略并清理全部缓存”不得顺带丢弃。明确放弃需说明密钥尚未另存且将不可恢复；已登记的用户文件始终不在缓存删除范围内。

生成的新密钥另存成功后，应用保留加密结果副本并明确列在“已另存密钥的加密缓存”；可单独清理该副本，已另存文件及登记信息保持不变。登记既有文件仅保存引用；签名执行的短时输入快照在任务结束后清理。

07 实现与复用边界

实际新增模块为 signing.rs（工具与证书）、signing_tasks.rs（敏感计划、任务与恢复）、signing_commands.rs（IPC 与文件对话框）、SigningTools.tsx（页面）。下表说明复用边界；专用提交入口不将密码交给通用引擎。应用自带编译为 Java 17 的桥类，运行无需 javac，官方签名库继续来自用户 SDK。

现有能力与新增工作

现有模块复用与需要扩展的部分
java.rs复用运行时发现、检测与私有运行时准备。新增独立 keytool 探测与版本检查，不能假定已有私有 JRE 一定提供该工具。
phone_apk.rs提取通用 Build-Tools 定位和签名验证适配器，保留现有分包安装行为。当前仅提取 SHA-256 的逻辑不足以表达未签名、警告、签名方案与轮换信息。
process.rs复用无 shell 的参数传递、隐藏工具窗口、有界输出、stdin、超时与取消。新增敏感输入封装，保证错误与进程摘要不含密码。
plans.rs / engine.rs复用计划摘要、requestId 幂等、任务阶段、资源互斥和取消。增加 keystore_create / apk_sign，执行上下文使用有类型的敏感参数；不能把两种密码塞入通用 Operation.args。秘密消费必须与幂等提交关联，响应丢失后返回同一任务。
storage.rs / recovery.rs新增 Keystore 登记表与非敏感证书快照，跟随既有迁移和备份机制；增加结果提交日志、启动复查和新密钥保护，避免恢复时重复生成。
exports.rs / TaskCenter.tsx现有产物清理仅允许截图、视频、文本导出，必须显式增加 APK、公开证书和受保护 Keystore 类型及路径归属校验，不能简单扩展为任意路径删除。
App.tsx / contracts.rs增加导航页与 SigningTools.tsx；同步导航偏好白名单、中英文、原生 IPC 权限及 Rust → TypeScript 契约，继续由生成流程更新 bindings。

建议的数据与接口

KeystoreRecord 保存 id、名称、规范路径、用途、关联包名、备注、上次文件摘要与检查时间；KeyEntryInfo 保存 alias、条目类型、算法和公开证书信息。ApkSignatureReport 分别表达文件摘要、验证状态、签名方案、签名者、工具版本及警告。证书快照带来源与检查时间，不能用“上次成功”覆盖当前失败。

建议增加 signing_environment、keystore_register / inspect / update / forget、certificate_export、apk_signature_inspect、apk_sign_prepare 与专用敏感授权 / 提交命令。普通计划和任务 DTO 只携带非敏感引用；秘密由独立内存上下文提供，专用提交入口仍复用现有计划与 requestId 规则。

文件选择限制为相应用途，校验路径、类型、大小与读取上限。Keystore 列表读取采用固定工具语言、结构化边界和证书编码解析；不直接信任本地化提示文字。keytool 提示顺序、格式识别和谱系检测方案在 S0 固定，不将未验证的输出解析直接接入写操作。

08 实施顺序与完成条件

第一轮分四个阶段交付。S0 完成工具与敏感输入可行性验证后冻结接口；S1 / S2 可分别评审，S3 完成整个功能闭环。不预先承诺日历工期或版本号。

S0 · 工具与密码通道

验证当前 Java / 私有 JRE 的 keytool 能力、JKS / PKCS12、双密码、中文与空格路径、Unicode 密码、Build-Tools 的对齐参数，以及单签名者 / 轮换信息的可靠识别。形成有界工具适配层、敏感输入类型和明确的不支持分支。

完成条件：临时测试密钥可读取与签名，密码不进入任务参数、SQLite、日志、命令行或临时文本；无法可靠识别的情况有阻止写入路径。

S1 · Keystore 管理闭环

完成导航、登记列表、alias 详情、公开证书导出、新建及结果保护；接入数据库迁移和受保护文件恢复。

完成条件：已有文件原件不变，新密钥可独立重新打开，生成后中断不会失去原结果，移除登记不删除文件。

S2 · APK 校验与证书对比

完成未签名 / 无效 / 有效 / 不确定状态、签名者与方案展示、公开证书对比和依赖准备流程。

完成条件：篡改 APK 无法显示有效，角色备注不影响比较，上传证书与商店证书差异得到准确解释。

S3 · 签名、另存与安装衔接

完成签名计划、输入快照、对齐、签名、复查、新文件发布与已有目标替换、取消与结果恢复；输出可进入现有安装面板。补齐本功能针对性回归和使用说明。

完成条件：第 09 节适用验收项全部形成证据，现有分包安装、任务中心、Java 配置和退出保护无回归。

本轮只验证新功能所需的工具与文件边界，不恢复已取消的一期长时压力、全量手机 / 硬件 / 干净系统 / 混合 DPI 矩阵或 Authenticode 工作。

09 第一轮验收标准

编号场景通过标准
SK-AC01登记、重复登记与移除同一路径定位到同一记录；原文件摘要不变；移除记录后文件仍可独立读取。缺失文件保留记录并能重新定位。
SK-AC02格式、alias 与密码JKS / PKCS12、多个 alias、纯证书条目和 JKS 双密码被正确识别；密码错误或格式不支持不误报可用。已登记快照与当前检查状态分开。
SK-AC03新建与目标冲突生成文件可用独立 keytool 重新打开；格式、alias 与证书符合表单；既有文件、同路径及路径别名不会被覆盖。
SK-AC04指纹与公开证书SHA-1 / SHA-256 与独立工具结果一致；PEM / DER 可重新解析并对应同一证书；导出不含私钥。
SK-AC05APK 签名验证未签名、有效、篡改和无法识别案例结果明确；警告保留；多签名者与轮换案例不能被简化成普通单证书结论。
SK-AC06证书比较与 Play 角色相同与不同证书判断准确；角色仅作备注，不能把上传证书与分发证书不同直接认定为异常，也不能承诺覆盖升级。
SK-AC07普通单 APK 签名独立 apksigner 校验新产物通过，证书与用户所选一致，对齐检查通过；另存到不同输出位置时输入 APK 摘要不变，所有模式的 Keystore 摘要不变。显式覆盖模式在原路径得到验证后的 APK，既有签名仍需单独确认替换；分包与不支持谱系输入阻止写入。
SK-AC08秘密与重复提交用专用测试密码检查任务参数、数据库、日志、命令行和应用暂存，均无密码内容；授权过期重新输入；响应丢失后同一 requestId 返回同一任务，不重复签名或生成密钥。
SK-AC09输入变化与发布冲突确认后输入、已有输出或工具变化要求重审；原先不存在的目标在发布前被其他程序创建时不覆盖。空间不足、文件锁和验证失败无假成功。
SK-AC10新密钥与产物恢复在生成后、发布后及登记前注入中断，重启能找到原密钥或原输出；重试保存同一结果，不生成替代密钥。未保存密钥不被任务删除或普通缓存清理丢弃。
SK-AC11取消、托盘与完整退出取消仅作用于自有进程与暂存；最小化 / 关闭不终止已提交任务；完整退出保护未保存 APK 与密钥；模拟器及共享 ADB 保留。
SK-AC12依赖、界面与安装衔接缺 keytool / zipalign / apksigner 时给出准确入口；中文 / 空格路径与兼容工具的 Unicode 密码可用；中英、主题、键盘和紧凑布局可操作。签名结果经独立确认安装到专用模拟器，并验证现有目标保护规则。

验收使用隔离的临时密钥、样例 APK、专用数据目录和专用模拟器，不读取或修改真实发布密钥。已执行的证据及尚未覆盖的人工或故障组合逐项见 实施报告，不将接口实现或历史测试替代未执行场景的验收。

10 依据与后续候选能力

外部工具规则于 2026-11-01 核对；功能边界、默认参数、授权期限与实施顺序为本方案的产品选择。正式实现记录实际使用的 Java 与 Build-Tools 版本，并以可复现结果冻结兼容范围。

  • Android Developers · Sign your app：上传密钥、应用签名、证书有效期及 Play App Signing。
  • Android Developers · apksigner：签名与校验、密码输入方式、签名方案与轮换。
  • Android Developers · zipalign：签名前对齐、对齐校验与 16 KiB ZIP 对齐。
  • Oracle JDK 21 · keytool：Keystore 格式、证书与条目操作、密码交互。

后续候选能力：显式导出加密 Keystore 备份及校验、修改密码和 alias、格式转换、AAB 签名、整组分包处理、系统凭据存储、轮换谱系与批量操作。这些仅作方向参考，尚未排期，不自动形成开发待办。任何修改既有密钥容器的功能都应另行设计备份、复查和恢复流程。
