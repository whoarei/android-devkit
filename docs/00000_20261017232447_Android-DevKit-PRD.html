Android development environment

Android DevKit产品需求与交互设计

面向主要使用 AI 编码工具和轻量编辑器的 Android 开发者，提供独立的 SDK、模拟器与设备管理入口，让开发环境准备和应用验证无需打开完整 IDE。

版本 v0.6日期 2026-10-17范围 本地桌面工具首发建议 Windows 11 x64

核心产品判断　围绕“准备好环境，并在正确设备上验证应用”组织产品。默认进入设备工作台，复用已有 Android 环境，通过清晰的任务状态和可操作的故障解释减少反复查命令、切工具的成本。

本方案聚焦 SDK、模拟器、设备管理及桌面窗口的功能需求与交互设计。文中的界面是低保真交互示意，不连接真实设备。

01产品定位与目标

要解决的问题

当代码编写、修改与构建主要在外部编辑器或 AI 编码工具中完成时，用户仍需要管理 SDK 组件、启动模拟器、连接真机，并把构建产物安装到设备。工具将这些操作集中到独立工作台，提供清晰的环境状态、设备目标与故障处理入口。

Android DevKit 定位为本地 Android 开发环境与设备管理工具。用户可以单独打开它完成设备相关工作，也可以把设备标识和环境信息交给现有编码工具继续使用。

用户应获得的结果

  • 第一次使用能走通。 已有 SDK 可以直接复用；没有 SDK 时按使用目的准备最小必要组件，明确下载量、目录和剩余步骤。
  • 日常操作能快速完成。 打开即看到设备，启动常用模拟器、安装 APK、截图和查看日志都有直接入口。
  • 失败后知道怎么办。 区分连接、授权、系统启动和任务执行状态，给出针对当前问题的下一步操作。
  • 与现有开发流程共存。 SDK、AVD 和 ADB 的实际来源可见，支持与 Android Studio、外部终端及编码工具同时使用。

产品边界

首版覆盖环境管理与应用运行验证，不纳入代码编辑、项目索引、布局编辑器、完整断点调试、性能分析器和发布签名工作流。构建由外部工具完成，首版接收 APK 作为输入。这样才能把产品复杂度集中在用户明确高频使用的三类能力上。

核心用户故事

  1. 我已安装 Android Studio，希望直接看到已有模拟器并启动，不再配置第二套环境。
  2. 我刚拿到一个 APK，希望把它安装到选定的真机，清楚知道安装是否成功。
  3. 我需要一个指定 Android 版本的模拟器，希望工具帮我补齐镜像并检查能否运行。
  4. 我的手机“插上了但不能用”，希望知道是未授权、驱动、连接线还是 ADB 状态问题。
  5. 我想把错误日志和设备环境交给 AI 继续排查，希望一键复制或导出有范围的诊断信息。

首版不以云真机、远程设备集群、系统刷机或固件开发为目标场景。

首发平台建议

建议先支持 Windows 11 x64，覆盖本地 USB、无线 ADB 和硬件加速模拟器。macOS 与 Linux 在后续版本分别建立验证矩阵。界面设计保留跨平台行为，但首版不作“三端均已支持”的承诺。WSL 内构建可以作为外部使用方式，首版只管理 Windows 主机侧环境，不自动推断或修复 WSL 与主机的网络映射。

04信息架构与界面布局

采用单主窗口，顶部使用自绘标题栏和窗口控制按钮。默认页是设备工作台，使用“全部、真机、模拟器”筛选，而不是让用户在两套设备管理界面间切换。SDK 管理是第二个主页面；任务中心、环境诊断和设置作为辅助入口。无需先选择或导入代码项目。

自绘标题栏与窗口控制 WIN-01P0

标题栏由应用统一绘制，与内容区使用一致的色彩和图标。左侧显示应用标识与名称，中间保留可拖动空白及必要的环境信息，右上角按最小化、最大化或还原、关闭的顺序排列。无需额外叠加一条系统默认标题栏；关闭按钮始终位于窗口最右上角。新建模拟器等向导在主窗口内容区完成，共用这套窗口控制。

标题栏基准高度为 40 个逻辑像素，窗口按钮点击区域建议为 46 × 40 个逻辑像素。图标使用简洁线条，正常、悬停、按下与窗口失焦状态均可辨认；关闭按钮悬停时使用红色背景与白色图标。最大化后切换为还原图标及“还原”提示，状态取自真实窗口，不由按钮点击次数推断。

自绘窗口控制的行为要求
控件或区域交互行为状态与边界
最小化将主窗口最小化至系统任务栏下载、安装与设备会话继续；不等同于退出或转入托盘
最大化或还原普通窗口最大化；最大化状态下还原到先前尺寸与位置图标、提示与实际状态同步；最大化范围遵循当前显示器工作区
关闭进入统一关闭流程，处理进行中的任务与已配置的托盘行为不得绕过任务确认，也不直接结束模拟器；详见通用交互规则
标题栏空白区拖动移动窗口；双击在最大化与还原间切换按钮、下拉框等交互区域不响应拖动；支持从最大化状态拖动还原
系统窗口操作保留系统菜单、边缘缩放、系统贴靠和键盘窗口操作Windows 11 需验证最大化按钮的贴靠布局入口；多显示器和不同缩放比均可用

窗口按钮必须有可访问名称和明确的焦点状态。通过按钮、标题栏双击、任务栏或系统快捷键改变窗口后，界面表现保持一致。不同 DPI 下点击区域、图标和拖动区同时缩放，避免出现视觉按钮与实际响应区域错位。

主界面的职责

  • 顶部显示当前环境名称和可查看的 SDK 路径。环境异常时显示具体问题入口，避免仅出现一个没有解释的红点。
  • 列表承担设备选择和高频操作。选中行后，右侧详情区展示配置、连接方式、应用与日志入口；窗口较窄时详情改为抽屉。
  • 底部显示进行中的任务摘要。点击展开任务中心；切换页面不影响下载、安装或模拟器启动。
  • 当前操作目标显示在操作区内。详情区、安装对话框和日志面板都重复显示设备名称与序列号末段，防止多设备时误操作。

05首次使用与环境准备

首次打开先做有限范围的环境扫描，扫描期间即可进入界面。检查标准安装目录、相关环境变量及用户指定目录，不遍历整块磁盘。扫描结果区分“可用、缺少组件、路径不可写、无法识别”，让用户选择如何继续。

复用已有环境

  1. 展示候选 SDK 的路径、占用、主要工具版本及发现来源。存在多个有效目录时让用户明确选择；不把扫描顺序当作选择依据。
  2. 选择后读取组件和既有 AVD，显示“将复用此目录，不需要重新下载”。无法管理的 AVD 仍可显示原因与详情。
  3. 工具可用即可进入工作台。缺失能力在使用时引导补齐，例如只缺系统镜像不应阻止 USB 设备管理。

准备新环境

先询问使用目的，再生成组件计划。只连接真机准备设备通信所需工具；使用模拟器增加模拟器程序及选定镜像；准备外部构建环境可选安装 SDK Platform、Build Tools，并提示构建所需 JDK 等条件。构建准备不代表本工具接管 Gradle 构建。

默认目录应属于当前用户且可写。SDK、AVD 数据与下载缓存分别说明位置；支持选择 SDK 和 AVD 目录，展示所在卷的可用空间。安装前列出下载大小、预计新增占用与临时空间；上游不提供可靠数值时标为“估算”或“待获取”，不显示伪精确值。

所需许可必须由用户查看并接受后继续。拒绝时保留已选配置，说明哪些能力尚不可用。只有当前工具链确实需要 Java 且本机缺失时，才引导选择或安装兼容运行时。

验收 ONB-01　在存在有效 SDK 的测试机上，首次打开无需安装 Android Studio，无需重新下载已有组件，即可看到已有 AVD 或已连接设备；未识别到环境时，用户可以从安装计划继续完成首次准备。

06SDK 管理

查看与选择组件 SDK-01P0

按“平台、工具、系统镜像”组织组件。默认显示已安装内容及稳定渠道的推荐项，预览版和过时包收在筛选项中。搜索支持 Android 版本、API Level、名称及组件 ID。每行显示组件名、版本、安装状态、占用或下载量；展开后显示来源与完整标识。

“推荐”应说明理由，例如“与你选择的模拟器架构匹配”或“当前已安装工具的稳定更新”。不可把最新版本作为所有项目的默认升级目标。SDK Platform、Build Tools、系统镜像分别解释用途，避免用户误以为安装平台包就获得了可启动模拟器。

先确认计划再执行变更 SDK-02P0

勾选安装或卸载项后，页面底部出现待执行清单；点击“应用变更”才进入确认步骤。确认内容包括组件及版本、新增与移除项、目标目录、下载量、空间变化和许可。安装成功以工具结果与安装清单复查为准，不能只依据进度条到达 100%。

版本可并存的组件允许选择具体版本；无法并存的组件应展示“将替换当前版本”，不暗示支持任意回滚。更新采用显式选择，首版不在后台自动升级工具或批量更新全部组件。

处理共享依赖与下载失败 SDK-03P0

卸载系统镜像前列出引用它的已知 AVD。镜像仍被引用、组件正被本应用任务使用，或目录被其他工具占用时阻止该项变更，提供定位入口。对未知外部项目依赖明确说明“无法检测全部外部引用”，不能把“未检测到”写成“无人使用”。

下载任务显示排队、下载、校验、安装及完成阶段，包含当前组件、已知进度和最后更新。失败可查看原因、修改代理并重试当前项；已完成组件保留。仅在下载源与工具支持时承诺断点续传，否则重新下载当前未完成文件。

SDK 页面显示最近一次刷新时间。断网时可查看缓存的已安装状态并启动已有设备，在线仓库查询标记为不可用。网络测试应访问实际组件源，不能只用通用网站连通性判断。

验收 SDK-AC　选择两个组件后可在一个计划内确认；其中一个失败时清楚显示各项结果并仅重试失败项。卸载被 AVD 引用的镜像时，必须列出受影响设备并阻止直接移除。

07模拟器管理

识别与管理已有模拟器 AVD-01P0

启动时读取配置的 AVD 路径与标准目录，保留既有名称、配置和位置。列表显示设备名称、Android 版本、API、架构、镜像类型、磁盘占用及运行状态。配置缺失或镜像不可用时保留设备条目，显示“缺少系统镜像”及修复入口。

运行中的模拟器只有一条记录，并关联 ADB 序列号。若无法可靠关联，从“待识别的模拟器会话”进入诊断，不猜测归属。对正在被 Android Studio 或其他工具使用的 AVD 展示占用状态；修改配置与数据删除遵循同一份占用检查。

按三个步骤创建模拟器 AVD-02P0

  1. 选择设备形态。 先选手机或平板，默认推荐适合主机资源的常用配置。展示屏幕尺寸和分辨率，硬件参数可展开调整。
  2. 选择系统。 Android 版本与 API 联动显示，优先列出匹配主机 CPU 和工具能力的镜像。区分 AOSP、Google APIs 和 Google Play；说明是否包含所需服务，不把不同镜像视为同一选项。
  3. 确认与创建。 名称、内存、存储、图形模式、数据目录有默认值；高级参数折叠。汇总缺失组件、下载量、磁盘需求和硬件加速检查结果。主按钮按实际动作显示“创建”或“下载并创建”。

镜像缺失可在流程内加入任务，无需用户跳到 SDK 页面再回来。用户取消向导时不会留下未完成的 AVD 配置；已完成的共享镜像下载保留并说明。创建完成后提供“启动模拟器”，是否自动启动使用清晰的可选项，不额外猜测用户意图。

启动与运行 AVD-03P0

点击启动后立即反馈“正在启动”，再区分进程创建、ADB 连接与系统就绪。只有设备通信可用、系统启动检查完成后才显示“可用”；进程存在或 ADB 刚出现都不能等同于系统已就绪。首版使用官方模拟器独立窗口，通过“打开窗口”聚焦运行实例。

同一 AVD 启动中时不允许重复启动。默认采用可用的正常启动方式；“冷启动”放在更多菜单，用于绕过异常快照。停止操作先发送正常退出请求，超时后才出现“强制停止”，并说明可能丢失未保存状态。

编辑与清理 AVD-04P0

停止后可编辑名称、内存及支持调整的常用参数，保存前验证范围。对既有 AVD 中无法可靠编辑的字段只读保留，不能覆盖未知配置。运行中修改要求先停止，编辑表单暂存用户输入。

“清除数据”与“删除模拟器”是两个独立动作。清除数据重置该模拟器的应用和用户数据；删除移除配置及其数据，但不顺带删除共享系统镜像。确认框明确列出设备名、数据目录、影响与预计释放空间。释放空间在操作后重新统计，不能把镜像体积计入每个 AVD 的可回收体积。

验收 AVD-AC　用户从工作台完成镜像下载、创建与启动；同一设备在启动前后无重复条目。设备启动卡住时能查看阶段与日志，冷启动可重试，且不会自动清除数据。

08设备管理

USB 连接与设备详情 DEV-01P0

插入设备后自动刷新列表，无需点击全局刷新。显示型号、Android 版本、连接方式、序列号和当前状态；支持本地备注名，保留原始型号供排查使用。未授权设备显示“请解锁手机并允许 USB 调试”，配套简短步骤；不得把它归类为未发现设备。

未检测到设备时提供连接向导，按开发者选项、USB 调试、数据线与端口、系统驱动、ADB 状态依次检查。驱动相关提示给出官方来源和明确适用条件，不自动安装来源未知的通用驱动。

无线配对 DEV-02P0

  1. 点击“连接设备”，选择无线连接，提示手机开启无线调试并与电脑位于适用的同一网络。
  2. 首版提供配对码方式，表单包含设备地址、配对端口与配对码。区分“配对端口”和后续“连接端口”，不要默认相同。
  3. 配对成功后进入“正在连接”，通过发现或用户输入的连接地址建立会话。设备实际可通信后才显示连接成功。
  4. 自动发现失败时提供手动输入、网络隔离检查和重新配对入口；过期配对码清楚提示重新获取，不无限重试。

界面按本机工具与设备的无线调试能力展示连接选项；能力不足时说明原因并提供 USB 连接入口。P0 不默认开放旧式无配对的网络 ADB 模式。

明确操作目标 DEV-03P0

列表单选建立当前查看目标，常用设备可设为默认目标。安装、截图和日志任务在发起时绑定设备；目标断开后原任务失败或等待用户处理，不能自动转移到其他在线设备。多个可用设备且目标未明确时，先展示设备选择器。

真机同时出现 USB 与无线连接时，只有身份信息可靠才合并成一个设备，并让用户选择活动连接。无法确认时独立展示连接方式与序列号，避免错误合并。无线“断开连接”与“取消配对”分开，撤销手机侧授权需给出设备端操作指引。

安装并验证应用 DEV-04P0

支持选择或拖入单个 .apk。拖到指定设备行时以该设备为候选目标；拖入空白区时使用当前目标或要求选择。安装面板必须展示设备名、序列号、文件名、大小，以及能够可靠读取的包名和版本。默认允许用户确认后覆盖安装并保留应用数据，不自动卸载旧应用。

安装前尽可能识别最低系统版本与 ABI 兼容性；无法读取时说明将依据设备安装结果判断。签名冲突、版本降级、存储不足分别给出操作建议。“卸载后重装”需再次说明该应用数据将丢失，由用户明确触发。单文件 AAB 和分包安装首版不支持，选择后解释所需产物类型。

安装完成显示“已安装”，并提供“启动应用”。仅在包名与可启动 Activity 能被可靠识别时提供启动能力；否则保持安装成功结果，说明不能自动启动的原因。不会把安装完成直接称作应用运行正常。

观察结果与导出 DEV-05P0

设备详情提供基础 Logcat：设备与应用过滤、级别、关键词、暂停、清空当前视图和导出。界面滚动缓冲默认最多 10,000 行，达到上限滚动淘汰并提示；长时间采集通过单独的文件导出任务执行。应用进程重启后重新关联过滤条件，避免 PID 变化导致日志看似消失。

截图完成可预览、保存或复制，失败时不留下“保存成功”的提示。环境摘要包含系统、工具版本、设备型号、系统版本和任务错误；默认脱敏用户目录、设备标识、IP 与可能包含敏感内容的日志字段。用户可以预览并选择是否保留详细标识，再交给外部编码工具。

验收 DEV-AC　USB 未授权与完全未连接有不同引导；无线配对成功但未连接不显示可用。安装到 A 设备时，即使用户选中 B 设备或 A 断开，也不能将安装转给 B。

09端到端任务流程

场景 A 复用已有环境验证 APK

打开工具读取既有 SDK 与 AVD
→
启动常用设备显示启动阶段与就绪状态
→
拖入 APK确认目标并安装
→
观察与反馈启动应用、截图或导出日志

成功条件：无需打开 Android Studio；用户能确认使用了哪个环境、安装到了哪个设备，并取得用于继续排查的结果。若所选模拟器未就绪，可显式选择“就绪后安装”；这是有超时且可取消的等待任务，不能成为无限期隐藏队列。

场景 B 新环境创建一个测试模拟器

  1. 环境扫描无结果，用户选择“创建环境”和使用目的“使用模拟器”。
  2. 选择手机或平板及系统版本，工具检查架构、加速、路径和磁盘空间。
  3. 用户确认组件计划与许可，任务中心下载并安装缺失项。
  4. 组件准备成功后创建 AVD。用户启动设备，系统就绪后回到可操作的设备详情。

失败分支：下载失败停在具体组件，可重试；加速条件不满足时显示系统级处理步骤，并允许改用真机继续工作。不能把进入 BIOS、开启系统功能或重启电脑当作静默自动修复。

场景 C 真机连接异常恢复

  1. 已检测到手机但未授权，设备行显示授权步骤，安装按钮不可用且可查看原因。
  2. 用户在手机授权后，状态自动转为可用，不要求重新插拔。
  3. 若仍不可用，进入该设备的诊断页，显示已检测事实、可能原因和优先处理步骤。
  4. 需要重启 ADB 服务时说明可能影响本机其他工具及设备连接，用户确认后执行并重新扫描。

与 AI 编码工具的衔接

P0 提供“复制设备标识”“复制环境摘要”“导出本次日志”等明确动作，由用户决定将哪些内容交给外部工具。P1 的 CLI 或 MCP 接入应复用同一套设备目标和任务规则：读操作可以直接查询；写操作可审计，破坏性动作按授权策略确认；并发任务不能绕过资源占用限制。首版不引入常驻 AI 聊天窗口。

10状态与异常交互

设备状态回答“能否操作”，任务状态回答“这个动作进行到哪里”。两者分别展示，例如设备可用时 SDK 下载仍可能失败；不能用一个全局“异常”覆盖所有信息。

11通用交互规则

操作反馈与任务持续性

点击后立即显示局部反馈。轻量成功提示可以短暂显示，但安装结果、失败原因和后台任务必须留在任务中心。执行中的任务允许切页；相同资源上的冲突写操作排队或禁用，并说明等待对象。不同设备上的独立操作可并行。

关闭窗口默认退出界面；存在下载或安装时显示具体任务，提供“返回”“完成任务后退出”“取消任务并退出”。取消能力取决于阶段，不能中断会破坏状态的写入。若用户显式开启托盘运行，关闭可转入托盘，并在首次发生时说明；托盘中仍能看到任务数量和失败状态。

退出管理界面与停止模拟器分开。已有模拟器通常继续运行；用户选择停止时才结束实例。安装任务或未保存导出结果不得因关闭窗口静默丢失。

高影响操作的确认

动作确认内容默认行为
清除 AVD 数据设备名、被清除的数据和不可恢复性先停止设备，明确确认
删除 AVD配置与数据目录、释放空间、共享镜像保留明确确认，不联动删镜像
卸载应用后重装目标设备、包名和应用数据丢失仅由用户主动选择
卸载 SDK 组件组件版本、已知引用、外部影响范围已知依赖存在时阻止
重启共享 ADB 服务会中断其他开发工具和设备连接明确确认，不作为自动修复

普通导航、查看详情、启动已停止的模拟器和复制非敏感标识无需增加确认。确认按钮使用动词描述，如“清除该模拟器数据”，避免只写“确定”。

环境变更与共存

默认使用应用内选定路径，不静默修改系统 PATH、JAVA_HOME 或其他工具配置。若用户需要设置 ANDROID_HOME，先展示新增或修改内容，执行后说明新终端才会读取。检测到 ANDROID_SDK_ROOT 与其不一致时提示解决冲突。

首版选定 SDK 后不提供一键迁移或自动清理旧目录。外部工具修改 SDK 或 AVD 时刷新实际状态；发现未保存的编辑与外部更改冲突，保留输入并让用户重新载入或另存配置。

可访问性与信息密度

主操作支持键盘访问，焦点清晰；列表方向键选择、Enter 打开详情、Escape 关闭可取消面板。状态同时使用文字与图标，不只依赖颜色。建议主窗口最小 960 × 640，窄屏用详情抽屉；100% 到 200% 系统缩放下关键动作可见。路径可省略显示，但可复制完整值。
