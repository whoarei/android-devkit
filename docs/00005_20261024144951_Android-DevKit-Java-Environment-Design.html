现状与设计边界

已有能力可以复用

设置页已有 java.exe 路径。初始配置会尝试 JAVA_HOME 与常见 Android Studio JBR 路径；“模拟器最小环境”能按需下载应用私有 Temurin JRE 21。

当前普通 SDK 操作通过 sdkmanager 执行，Java 前置检查主要验证文件存在。路径存在并不能证明版本、架构或 SDK 工具兼容性合格。

本次新增交互

SDK 页面常驻精简 Java 状态；设置与诊断共用一个配置面板；安装计划增加环境预检和恢复上下文；Java 准备成为可观察的独立任务。

推荐沿用项目已固定的 JRE 21 运行时，不要求用户安装完整 JDK。项目编译用 JDK、Gradle JDK 管理与系统环境变量管理暂不纳入。

按实际操作检查依赖。Java 缺失会阻塞当前依赖 SDK Java 工具的安装、卸载或 AVD 创建步骤。目录浏览、组件勾选、下载源配置、使用已有 ADB 连接真机，以及启动已具备条件的模拟器，不应被一个全局 Java 错误屏蔽。归档下载本身不要求 Java，但本次方案在开始 SDK 安装任务前完成环境检查，避免下载完成后才报错。

代码依据：src/App.tsx 设置页；src-tauri/src/domain.rs 初始探测；src-tauri/src/plans.rs 与 engine.rs 的 bootstrap；process.rs 的 Java 工具入口；resources/bootstrap.json 的固定运行时。方案以仓库当前支持的 Command-line Tools 12～22 为范围。

入口与主流程

主入口：SDK 管理

进入页面自动执行轻量检测，不弹窗。缺失或失效时，在下载源下方显示“未找到可用的 Java / 配置 Java”；已就绪时收起为“Java 21 · 应用私有 · 可用 / 管理 Java”。

允许继续浏览和勾选。“查看安装计划”保持可用：存在 Java 问题时打开配置面板，保留组件、版本、操作类型、筛选、页签及滚动位置。

辅助入口：设置与环境诊断

设置 → Java 运行环境：显示版本、来源、实际路径、最近检测结果与“配置 Java”。替换现有只有路径输入的交互，使用同一面板。

环境诊断列出具体阻塞与“检测并配置”。准备开发环境、SDK 安装/卸载、创建 AVD 等依赖入口共用检测结果与修复动作。

选择 SDK 组件→检查运行环境→复用或准备 Java→验证并保存→重新生成安装计划→用户确认执行
  1. 检测已有环境。已配置且验证通过的 Java 直接复用。仅发现其他可用候选时，展示来源、版本和路径，提供“使用此 Java”；发现不代表自动覆盖当前用户配置。
  2. 没有可用环境。默认选择“一键准备应用私有 Java”；同屏保留“使用已有 Java”。前者展示体积、来源、安装位置、许可入口及生效范围；后者提供扫描结果或文件选择。
  3. 准备阶段独立记录。首次确认对应运行时许可后，下载 → 完整性校验 → 解压 → 启动验证 → SDK 工具兼容性验证 → 保存。显示真实阶段、进度和失败点；可转任务中心继续观察。
  4. 返回原操作。Java 验证通过后提供“返回安装计划”。重新验证组件、来源、许可、磁盘与依赖，展示新计划。只有再次点击“开始安装”才执行 SDK 变更；完成 Java 准备不构成 SDK 安装确认。
  5. 工具也缺失时合并准备。同一“运行环境未就绪”面板列出 Java 与 Command-line Tools，准备清单分别展示来源、体积与许可。原生下载与解压工具能独立引导，不允许出现“安装 Java 依赖 sdkmanager”的循环。

检测与配置规则

项目交互约定
配置方式一键准备私有运行时 / 使用已有 Java。已有 Java 可来自 JDK、JRE、Android Studio JBR；不要求存在 javac。可选择 java.exe；如接受目录输入则归一到 bin/java.exe，并回显实际文件。
候选发现顺序显式保存路径 → 已安装私有运行时 → Android Studio JBR → JAVA_HOME → PATH。按规范路径去重，保留来源标签；不对磁盘全量递归扫描。显式配置失效时保留失效信息与修复入口，不静默换到另一候选。
验证内容文件存在且可执行；实际启动并读取版本、供应商、位数与架构；用当前受支持 SDK 工具执行不改变 SDK 的启动验证。区分“Java 本身失败”和“Command-line Tools 缺失 / 损坏”。兼容标准按工具版本维护并以启动结果确认，不使用“任意 Java 17+ 均可”这类全局判断。
超时与取消建议 Java 启动检查上限 5 秒，SDK 工具启动检查上限 10 秒；此为实现目标，需用实机验证调整。检查使用无需联网且不接受许可、不写 SDK 的入口。超时显示“检测超时”，可重试；取消关闭受控子进程。
状态生命周期未检测 / 检测中 / 可用 / 未找到 / 路径失效 / 版本不兼容 / 架构不支持 / 启动失败 / 检测超时。Java 路径或文件、SDK 根目录、Command-line Tools 版本变化后使对应兼容性结果失效。执行任何依赖操作前重新快速核验。
推荐运行时沿用现有 Temurin JRE 21 Windows x64 固定发行包；原型体积约 46.7 MiB，正式页面从清单读取准确体积和版本。私有目录位于应用数据目录，不安装到系统，不改系统 PATH / JAVA_HOME / IDE 配置。
私有准备与保存先下载到暂存目录，核对随应用可信发行清单固定的 SHA-256，安全解压并验证运行时和工具兼容性；全部通过后原子切换应用路径。存在同名损坏目录也不能直接视为已就绪。失败保留原配置，不把半成品作为候选。
网络与来源Java 沿用现有手动代理，但使用独立的 Adoptium 官方发行地址（当前为 GitHub）；Google / 腾讯 / 自定义 SDK 根地址不适用于 Java。面板默认只显示摘要，详情展开完整下载地址和校验依据。
离线与下载失败首版通过“使用已有 Java”选择离线解压好的受信任 JDK/JRE/JBR，检测通过即可使用。不在首版引入任意 JDK ZIP 导入器或未知镜像。下载失败保留组件选择，提供原源重试、检查代理和使用本地 Java。
许可私有运行时显示并确认随包附带的完整许可，沿用现有按许可文本哈希保存的确认机制；同版本已确认可复用。Java 许可与 SDK 组件许可分开，准备前能看到实际将下载的内容。
任务与配置一致性Java 准备独立任务，允许关闭面板后继续；关闭用“转到任务中心”，取消才停止任务。依赖当前 Java 的任务运行时，面板可查看、扫描与验证候选，切换按钮禁用并说明“相关任务结束后可切换”，不后台自动应用。相关任务终结后由用户应用。
只改 Java 配置保存仅更新经验证的 Java 设置，并同步设置页表单；不能用旧表单覆盖其他已更新配置。原始 SDK 计划绑定配置版本，变更后重新生成；网络源、组件版本或依赖已变化时展示差异再确认。
取消与重启恢复取消只停止准备，暂存文件清理或保留为隔离下载缓存；原 SDK 选择保留。重启读取任务状态和有效配置，允许复用已校验完成的运行时，保留原操作草稿供用户恢复。草稿失效时明确原因，不自动启动安装。

异常状态与恢复

触发场景用户看到什么下一步
首次使用，无 Java“未找到可用的 Java。浏览和选择组件不受影响；安装前需要配置。”推荐私有运行时，或选择已有 Java。
发现 Studio JBR“发现 Android Studio 自带 Java 21 · 验证通过”，显示路径。默认展示已有 Java 方式，点击使用后返回原操作；不修改 Studio 配置。
Java 太旧“检测到 Java 8，无法运行当前 SDK 工具”，详情展示实际工具要求与错误。切换已有候选或准备私有运行时；不提示用户先卸载旧 Java。
路径失效 / 架构不支持 / 启动失败具体路径、失败原因与最近检测时间；保存按钮禁用。重新选择或检测；只有验证通过才保存。
工具缺失“Command-line Tools 未就绪”，Java 检查结果单独显示。进入合并环境准备，避免误报成 Java 错误。
Java 下载超时“无法连接 Java 下载站点。SDK 安装尚未开始，组件选择已保留。”重试 Java 下载、检查代理、选择本地 Java；SDK 镜像设置不作为修复 Java 的默认动作。
校验失败 / 解压失败展示失败阶段；“未应用新 Java 配置”。校验失败时不继续解压。清理对应失败缓存后重新下载，或改用已验证的本地 Java。
空间不足 / 目录不可写安装前显示所需空间或无法写入的具体目录。释放空间、处理应用数据目录权限，或使用已有 Java；不默认要求以管理员启动。
准备中关闭 / 取消关闭只收起对话框，任务继续；“取消准备”才终止。任务中心持续可见。回到原组件列表；失败或取消后不丢失选择。
同时使用 Java 的任务未结束“相关任务进行中，结束后可切换 Java”，提供任务入口。可先检查候选，等任务结束后用户再应用。

交互与实现验收

  1. 全新 Windows 环境不安装系统 Java：仍能浏览 SDK 与切换来源；安装前出现配置入口。
  2. 无 Java 时选好多个组件，配置成功、失败、取消、后台完成后，选择与页面上下文均保留。
  3. 已有兼容 Studio JBR / JDK / JRE 时无需重复下载，明确用户确认后应用；显式配置失效不能静默替换。
  4. java.exe 存在但过旧、损坏、错误架构或启动超时，均不会显示“可用”或允许保存；修改路径立即使旧检测结果失效。
  5. Java 可用但 Command-line Tools 缺失，分别报告结果并能准备工具；两者都缺失时一次展示完整准备清单。
  6. 下载后的校验、解压、SDK 工具验证任一步失败，旧配置可继续使用，半成品不进入有效环境。
  7. Java 下载失败不会引导用户错误切换 SDK 镜像；离线选择本地 Java 检测通过后可继续。
  8. Java 准备完成不会自动开始 SDK 安装；原组件许可继续通过正常安装计划确认。
  9. 相关任务运行时不能切换 Java；结束后不自动套用待选配置。并发准备请求进入同一 Java 任务。
  10. SDK / 来源 / 工具版本变化后重新生成计划；取消确认不会执行过期计划，外部移动 Java 后能在操作前发现。
  11. 保存新 Java 后设置表单同步，后续保存网络等字段不会把旧 Java 路径写回；系统环境变量和 IDE 设置保持原值。
  12. 对话框可通过键盘操作，焦点限制在面板中，关闭返回原入口；进度与成功/失败有可访问状态提示；浅色、深色和窄宽度下内容不溢出。

当前交互原型演示主路径、本地路径检测、发现 Studio、版本/路径异常、下载超时、取消、后台任务与返回计划。真实 Java 执行、兼容性判定、并发锁、重启草稿恢复和网络传输属于后续实现验收，本原型不代表这些能力已完成。
