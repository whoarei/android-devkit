设备应用管理、安装包导入与投屏实施报告

三项能力已接入当前源码：应用管理、APKS / XAPK / APKM 导入、scrcpy 投屏控制。本轮纳入 v0.8.0，安装版、便携包和签名更新资产沿用现有发布流程；正式状态以对应 Release 为准。此前取消的一期 T-01～T-07 不恢复为待办。

已实现能力

能力用户入口与行为目标与结果保护
设备应用管理设备详情 → 应用管理；默认第三方应用，支持包名搜索、系统筛选、键盘选择、版本 / UID / API / 安装路径查看，以及启动、停止、清数据、卸载和导出 APK。绑定设备 epoch、transport-id、serial 和 Android 用户；执行前复查包名、版本、安装位置及完整安装 / 更新时间。清数据和卸载需确认；系统应用禁止停止、清数据和卸载。
完整 APK 导出单文件导出为 .apk；多文件包含全部已安装 base / split，保存为可重新导入的普通 .apks 集合，在待保存文件中另存。逐文件核对大小与设备 SHA-256，复查源应用身份；完整发布后登记，提交与登记间中断可按已记录摘要恢复。原应用和私有数据保持原状。
安装包容器设备详情 → 分包 APK 安装 → 导入 APKS / XAPK / APKM。含 toc.pb 的官方 APKS 通过 bundletool 按 API、ABI、语言、密度选包；普通集合按原生 ABI 优先级筛选。先暂存不可变副本；拒绝路径穿越、重复 / 链接路径、超量解压、无效 ZIP 和 OBB 扩展数据，再复用签名、版本、依赖和设备兼容性校验。选包集合绑定准备时连接，不能转投其他设备。
投屏与控制设备详情 → 投屏与控制；按需准备官方 scrcpy，选择控制 / 只读、最大边长及 30 / 60 FPS；独立窗口，关闭或停止任务结束。每次会话使用私有本地 ADB 代理，把 serial 选择改写为冻结 transport-id；仅暴露目标设备，拒绝共享服务控制。断线结束，无自动重连；仅结束自有进程。并行安装和传输可继续。
工具准备与界面官方工具以确认计划下载，显示进度、取消与失败；中英文、亮暗主题、窄屏、焦点约束、任务与退出流程沿用现有交互。固定 scrcpy 5.0.1 与 bundletool 1.18.3 的下载 URL、大小和 SHA-256，安装到本应用私有 tools 目录；启动前复查文件，活动投屏时禁止替换其工具。

兼容范围与待实机确认

  • 当前面向 Windows 11 x64；手机型号、OEM 安装限制、USB / 无线调试、实体手机输入与编码器组合仍需使用实际手机确认，本轮专用模拟器证据不计为全品牌手机验收。多 Android 用户的界面参数有夹具验证，真实专项使用用户 0，未实测用户切换矩阵。
  • XAPK / APKM 支持可读取 ZIP 中的 APK 集合，明确拒绝 OBB 扩展数据；不导入 AAB，不绕过加密容器或访问应用私有数据。普通集合包含无法可靠合并的变体时拒绝，用户可改用官方 APKS 按设备选包。
  • 应用列表以包名标识，不额外读取所有应用图标和显示名称；导出仅包含已安装 APK，不备份账号和应用数据。系统应用保持只读 / 启动 / 导出边界。
  • 投屏默认无音频、无自动剪贴板同步。控制模式的键鼠和 scrcpy 原生拖入会直接作用于当前设备，原生拖入在投屏窗口反馈，行为类似现有交互终端；独立的 DevKit 安装和传输仍走任务确认。
  • 本轮对应 v0.8.0；安装包、便携包和更新资产的正式状态见 Release 页面。旧版取消事项和二期实体手机待验范围沿用已有决定。
