二期循环审核与修复报告

审核交互设计、用户体验、架构边界与代码实现，共修复 18 组问题。
按“审查 → 修复 → 针对性回归 → 再审查”推进。末轮静态复审未发现新的可复现、可在当前环境修复的问题；这不等于覆盖所有手机和厂商系统。本报告复核时尚未另行发布。

1. 审核与收敛记录

  1. 首轮检查三条操作链及计划 / 任务交接，修复重复提交、错误可见性、旧清单、进度刷新与焦点问题。
  2. 第二轮复核存储发布、原件备份和恢复入口，修复最终内容核对、源任务互斥、旧历史可达性及孤立缓存管理，并增加提交点注入。
  3. 第三轮检查录屏落盘与登记的断点、依赖工具及输入边界，修复本机 MP4 恢复、明确放弃入口、工具排序、循环依赖与有限读取；修复后再次复核并运行完整回归。
  4. 收尾补审大目录与长响应：流式筛选 APK，提前限制待遍历队列，要求目录列表首尾标记完整；新增实际 SDK 的 10001 条目拒绝用例，并重跑最终发布核对与恢复专项。

2. 已修复问题

编号级别问题与用户影响最终处理及证据
R01P1提交重试会生成新请求 ID，响应丢失后可能重复执行同一计划保留 requestId，提交入口加同步防重锁，提交期间禁用返回 / 关闭；已验证丢失响应后重试 ID 相同。
R02P1发布响应成功后缺少最终内容复查，可能过早清理原件备份提交全部根节点后再核对最终类型、目录树、大小与可用摘要；异常保留备份。上传 / 下载分别在最终复查前注入外部修改，验证检测、拒绝覆盖和原件恢复。
R03P1完整 MP4 在文件落盘与登记之间强退，可能无法离线取回启动时识别并验证本机已完成的 MP4，幂等登记到待保存文件，无需重录或连接手机；不把 .part 当成完整视频。
R04P1未取回录屏的任务记录可被删除，丢失恢复入口未处理录屏原件保护任务记录；提供独立、明确确认的放弃原录屏计划，只清理本任务设备文件，保留本机 MP4，仍在录制时拒绝清理。
R05P2旧待恢复任务被最近 200 条工作台列表截断工作台额外保留未处理的二期待检查任务；用 205 条后续记录验证旧录屏恢复入口仍可达。
R06P2计划创建错误被全局 guard 吞掉，错误显示在弹窗背后二期调用使用可传播错误的统一计划入口；错误落在发起面板，操作进行时阻止重复创建计划，新计划清除旧错误。
R07P2新文件校验失败时仍展示旧的可提交清单重新选择后先释放未使用的缓存、清除旧清单，再显示本次结果；APK 校验失败后旧安装按钮消失。
R08P2传输提交后旧清单可再次提交，进度 / 完成反馈不连续提交成功立即补入任务回执，清除已提交清单；面板展示进度与取消，结束后刷新当前目录并核对选择项。
R09P2已清理失败任务仍持续显示恢复 / 清理卡片仅运行时写入清理完成标记；普通计划移除伪造标记，成功清理后移除无效入口。
R10P2放弃的 APK / 上传暂存持续占用空间关闭、重新选择、导航时释放未关联任务的应用缓存；启动清理超过 24 小时的孤立缓存。已关联任务的清单、载荷和恢复日志保留。
R11P2清理、恢复和缓存处理缺少对同一源任务的互斥对源任务使用独占使用权，防止不同连接或动作交错删除 / 恢复同一原件；同设备执行队列继续保留。
R12P2MP4 已安全保存后，设备清理失败会误报整体取回失败保留成功的本地结果，记录设备清理待办，并提供手动清理计划；清理后本机 MP4 仍能播放。
R13P2Build-Tools 按字符串排序，可能优先使用 9.x 而非 35.x改为数字版本排序，新增 9.0.0 / 35.0.0 / 35.0.1 用例；依赖任务结束后面板自动复查工具。
R14P2先选择 split 时，版本名称可能取自没有标签的 split版本名称以 base Manifest 为准，整组包名、版本码和证书仍须一致。
R15P2split 自依赖或间接循环未被预校验拦截加入有界依赖图检测；自环、间接环拒绝，合法依赖链通过。
R16P2目录权限失败可能被当成空目录，目标指纹读取缺少有限读取列目录先核对读 / 执行权限；本地内容摘要按已知大小加一字节有限读取，变化时拒绝；修正 10000 条目的边界。
R17P2弹窗及视频缺少键盘焦点约束，忙碌时焦点可能逃出设备操作、确认计划、视频弹窗开启焦点约束；忙碌且没有可用控件时仍保持在顶层对话框，包含视频原生控件，关闭后恢复原焦点。
R18P2超限目录可能先被全部读入内存，长目录响应被截断后可能误用残缺清单APK 目录最多保留 257 个候选，文件 / 备份遍历的待处理队列提前限额；设备列表加入首尾帧标记，前后截断均拒绝。工作台额外恢复条目不携带历史日志。新增实际 SDK 的 10001 条目拒绝与原文件保留检查。
