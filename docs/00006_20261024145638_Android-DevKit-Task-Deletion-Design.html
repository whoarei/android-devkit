任务删除

让历史记录可以被整理，同时保留正在执行的操作、尚未处理的文件和结果待检查的线索。沿用任务中心的两行摘要、状态筛选、30 项分页与详情展开方式。

交互方案 · 已确认2026-10-24 · 北京时间基于当前 TaskCenter 与本地任务存储本页为演示，不操作真实任务
推荐方案交互原型状态与范围文件处理反馈与异常验收要点

推荐方案

01 · 单条直接删除

条目右侧的垃圾桶点击即删除，不弹确认框。成功后移除记录并显示结果；删除中禁用重复操作，失败时保留原记录。

02 · 勾选批量删除

工具栏增加“管理任务”，进入后显示复选框与批量操作条。勾选后点击“删除所选（N）”直接执行。“全选本页可删除项”仅作用于当前页；翻页或改变筛选时清空选择并反馈。

03 · 按筛选直接清理

工具栏显示“清理历史（N）”，点击即清理当前关键词与状态下、跨全部页的可删除记录。范围、数量和跳过原因常驻显示在筛选下方，不增加预览或确认步骤。

删除的含义：移除任务记录和该记录的诊断内容，点击后直接执行，无需二次确认。不撤销已执行的操作，不卸载应用、SDK 或模拟器，不删除已另存的文件。文件处理仍独立进行；不把“取消”和“删除”合并。不提供回收站或“撤销”按钮。

条目布局：左侧保留任务名称与状态、目标/时间/结果两行信息，右侧固定排列重试/取消/处理文件、详情、删除等图标按钮。默认行高约 54 px；操作不换到条目下方。完整诊断按需展开，许可确认保持直接可见。

可点击交互原型

条目右侧的操作按钮集中排列，悬停或键盘聚焦可查看名称。点击垃圾桶直接删除；进入“管理任务”体验批量删除，或点击“清理历史（N）”直接跨页清理。

排队、运行中、待确认删除图标与复选框禁用跳过，显示数量说明“任务仍在进行，请先取消并等待结束”。保留原取消按钮和许可确认区。正在取消、当前步骤结束后取消仍按进行中处理。

待检查允许，点击直接删除；不增加勾选确认跳过，避免批量丢失排查线索必须先完成系统自动恢复检查且无写入/恢复资源占用。仍在恢复时禁用；状态和详情中保留结果尚未确认的说明。删除只移除记录，不会恢复设备或环境。

存在原始采集段右侧提供“处理采集”，复选框禁用跳过，显示数量先按需导出；在文件面板点击“清理原始采集”直接清理，不弹删除确认。清理完成后用户再自行删除任务记录。
输出/恢复状态读取失败，或资源仍被占用暂不可选，说明原因并提供刷新跳过，单独标记原因不能把读取失败当作“没有文件”；不能仅以任务状态结束判断执行器已释放资源。

选择只在当前页

进入管理时不选中任何任务。全选只选本页符合条件的项，不自动跨页；保留单条删除入口。关键词、状态或页码变化时清空选择，提示“筛选或页码已变化，已清空选择”。

清理范围必须可见

筛选下方常驻显示“关键词：… · 状态：… · 所有分页”，并列出可删除数和各类跳过数。无关键词、状态为全部时明确写“全部历史中的可删除任务”；无可删除项时显示 0 并禁用清理按钮。

点击时冻结范围

点击后按当时的搜索与筛选生成任务集合并直接执行。提交后新完成、新匹配的记录不加入；执行前重新检查状态、文件与资源占用，变化项跳过并报告。

文件处理：先解决归属，再删记录

当前待保存文件中，截图绑定任务；日志导出副本可独立存在；原始采集清单则依赖采集任务导出。因此不能直接删除任务行后留下失效入口。

点击“处理文件 / 处理采集”→按需预览、另存或导出→明确放弃的文件单独清理→返回列表，用户再次点击删除
对象建议交互保留与删除边界
截图与导出副本沿用待保存文件弹窗的预览、保存、忽略并清理；从任务进入时只显示该任务关联项。另存取消、失败或清理失败都不能解除保护。“忽略并清理”沿用现有缓存清理语义；已另存文件保持原样。独立导出副本持续在待保存文件中处理，不计入其来源任务的删除范围。删除任务不清空文件角标。
原始日志采集新增“处理采集”面板，显示段数、大小、采集时间及导出入口。面板内写明“清理后无法再次导出”，点击“清理原始采集”直接执行，无确认弹窗或复选框；失败保留任务和入口供重试。只清理归属该任务的应用采集目录。完成后原始采集入口移除，任务记录仍在，用户可继续删除。提示“已导出的文件保留，原始采集将无法再次导出”。若存在正在保存的导出/预览，先等待其完成。
已另存文件 / 环境结果列表下方统一说明“已另存文件及已执行的操作结果保留”。不触碰用户目录中的图片、文本、APK，不卸载 SDK、应用、Java、模拟器或回滚配置。删除任务不承诺释放这些空间。
已处理的截图缓存任务删除只影响记录；文件缓存清理由既有缓存机制单独负责。删除前必须解除文件元数据对完整任务行的强依赖，保存最小来源信息；后台不能因查询不到原任务而导致已处理缓存无法清理。不得把任务删除宣传成磁盘清理。

“处理采集”及独立清理原始采集是本方案的配套范围。若暂不实现，应保留此类任务并明确显示“暂不支持删除含原始采集的任务”，不能直接删记录后隐藏导出入口。

单条直接删除点击条目右侧垃圾桶后立即进入删除状态；不出现确认弹窗。记录实际删除成功后从列表移除。点击只提交一次；操作中禁用重复触发。完成后焦点移到邻近条目的右侧操作区，无邻近条目时回到工具栏。
批量 / 清理直接执行“删除所选（N）”与“清理历史（N）”显示当前数量，点击后直接执行；清理范围和跳过原因在列表上方可见。提交中显示“正在删除…”，禁用重复提交。不增加确认框、预览弹窗或待检查勾选确认；实际完成前不移除列表行。
成功“已删除 N 条任务记录”；记录消失，筛选计数与总数同步。保留关键词、状态与页码；末页空了回到最后有效页。无筛选且无记录显示“暂无任务记录”；筛选无匹配显示“没有匹配的任务”及清除筛选入口。
部分成功“已删除 8 条，2 条未删除”，提供“查看未删除项”；区分状态变化、文件未处理、占用与存储失败。成功项不再次提交。失败项留在原列表，结果面板可查看并选择“重试未删除项”；保护性跳过项引导处理文件/等待结束，不盲目重试。
全部失败 / 结果不确定存储失败显示“未删除任何记录，请稍后重试”；请求结果不确定显示“正在核对删除结果”。实际核对前不宣告全失败或成功，不清除选择。保留错误原因与重试入口，不只给瞬时提示。
后台变化“1 条任务仍在进行，已保留”；已被删除的项记为“此前已删除”，不算存储失败。点击时的范围不扩张。状态、文件与资源占用在执行时重检；存在未完成自动恢复提交的任务始终保护。新任务或重试任务不受影响。
键盘 / 窄窗口右侧图标常驻，具有可访问名称和焦点提示；禁用原因可在条目详情查看。按钮始终固定在条目右侧，不另占一行。窄窗口优先压缩摘要并截断长名称，完整文本可在详情查看；文件/结果面板关闭时返回触发点。完成和失败由可访问状态区播报。

实现约束

现有 task_list、task_cancel、task_retry 保持各自职责。新增可删除数量统计与直接执行能力，由原生侧计算完整历史范围、返回保护原因和逐项结果；前端不通过当前页数据估算跨页可删除数。

执行在点击提交时冻结任务集合并绑定操作标识，具有幂等性，无需用户再次确认。与任务写入、恢复提交、文件保存/导出互斥；每项先检查，再事务性移除任务及其专属诊断。必要的去重索引和资源归属信息需独立保留，避免删除 request_id 后重复执行旧请求。删除成功后让任务列表、工作空间、关闭状态等相关查询失效，避免轮询恢复已删除记录。

本方案不把“删除记录”承诺为安全擦除。SQLite 备份、审计与执行去重的留存规则需在实现时单独定义；实现不能把仍用于 AVD 归属判断或恢复提交的任务信息直接级联删除。

交互验收要点

  1. 单条删除、批量删除、清理历史点击后直接执行；不出现删除确认、预览弹窗或额外勾选。
  2. 排队、运行、待确认、正在取消、资源尚未释放和恢复未完成任务始终受保护；提交后状态变化同样受保护。
  3. 仅有待保存截图、另存取消/失败、原始采集尚在、文件状态读取失败时，不允许删除记录。
  4. 截图先保存或忽略，采集按需导出后点击清理直接执行；处理完成后不自动删除原记录，不改动已另存文件。
  5. 清理只匹配当前关键词与状态下的所有分页；页面常驻显示范围，跳过待检查和文件未处理任务，数量互不重复。
  6. 手动选择待检查任务也直接删除，状态与详情保留结果不确定说明；批量清理不包含该状态。
  7. 全选仅本页；翻页、改关键词、改状态清空选择并提示。轮询不自动扩张选择集合。
  8. 执行以点击时的集合为准，完成期间新结束任务、新重试任务和新生成文件不被顺带删除。
  9. 成功同步计数与列表，末页删除后回退；无记录与筛选无匹配两种空态文案有区别。
  10. 部分失败显示真实逐项结果，只重试未删除项；重复提交不会重复删除或重放任务操作。
  11. 删除记录后，关联文件缓存维护、原始执行去重、资源归属、应用关闭提示和重启恢复均无失效引用。
  12. 浅色、深色和窄窗口下操作按钮始终固定在条目右侧，默认两行摘要，不因操作另起一行；键盘能完成选择、直接删除和文件面板返回。

本页保留已确认的设计与模拟原型。对应应用功能已实施，实际存储、文件保护和恢复行为由原生侧完成；验证结果以项目测试为准。
